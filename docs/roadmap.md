# Roadmap

更新日期：2026-11-07。以下是尚未完成的工作，优先级表示建议顺序，不是发布日期或上线承诺。已交付能力见[功能清单](features.md)，历史变化见 [Changelog](../CHANGELOG.md)。

## P0：持续运行与运维

| 工作               | 当前缺口                                                                    | 完成标准                                                                         |
| ------------------ | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 统一生产部署布局   | 当前实例使用一个 Compose；`deploy.yml` 和发布脚本仍使用 releases/state 布局 | 对现有布局完成备份、迁移、镜像切换、失败恢复和回退演练，再启用服务器部署工作流   |
| 周期备份与异机恢复 | 已保留多次上线备份，尚无周期备份、异机副本及完整生产备份的异机恢复验证      | 明确保留期限、恢复点/恢复时间目标，验证数据库、角色、Redis、配置、文件和权限恢复 |
| 启用持续采集       | 线上自动采集关闭；有界连通性与有限页验收不足以证明持续更新                  | 在固定范围内验证六源分页、入库、失败退避和进程恢复，监控积压与覆盖后再启用       |
| 共享来源限流       | 当前 provider 门控在进程内；服务器、CLI 与测试流量不统一计量                | 按上游计量范围共享并发/速率和退避，正确处理 Crossref 响应头及来源认证参数        |

建议日常增量目标为每日一次，历史回溯使用独立低优先级预算；这是后续调度调整，当前实现仍为 72 小时。

## P1：覆盖与已有论文更新

| 工作                      | 当前缺口                                                        | 完成标准                                                            |
| ------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------- |
| 共享预印本采集            | 多主题、多路线可能重复请求同一日期 feed                         | 同一来源窗口只采集一次，保留各主题发现路径、预算和恢复语义          |
| 已知论文定期复核          | 仅依赖发现查询，不能完整捕获退出查询范围后的变化                | 对已纳入、待核和预印本安排有界复核，保留更新与人工结论的边界        |
| 正式发表关联              | bioRxiv/medRxiv 尚未消费独立 `/pubs` 关联流                     | 保存预印本与正式论文的可追溯关系，不混用两个版本的日期和身份        |
| 删除、勘误与撤稿          | PubMed 删除文件、arXiv deleted 标记及跨源生命周期关系处理不完整 | 形成可审计事件与展示，不物理删除历史论文或自动覆盖人工判断          |
| OpenAlex 与计算机文献补充 | OpenAlex、DBLP、官方会议目录和引文扩展尚未接入                  | 先确定访问额度、许可、检索/同步能力和成本，再完成来源适配与有界验收 |
| 召回质量评估              | 支持记录质量检查声明，尚无自动抽样校准                          | 建立人工核验集，区分未收录、未召回与分类错误，报告可复现的样本结果  |

OpenAlex 免费检索、季度快照和付费增量同步的能力不同，接入前按[来源政策](reference/sources.md#openalex-待接入对照)选型。

## P2：处理效率与可扩展性

- [ ] 区分引用计数等元数据变化与阅读材料变化，评估按材料哈希复用模型结果。
- [ ] 为复杂查询增加明确的语义模型与来源能力校验；当前不支持任意 AST、自动 MeSH 映射或邻近算子。
- [ ] 按来源许可制定原始响应与材料的保存、再分发和清理策略；当前响应哈希不能代替原文归档。
- [ ] 在现有累计模型配额之上增加供应商用量对账、周期预算和费用观察。
- [ ] 评估“发现后跨主题分发”的产品规则；当前仅评估已关联的发现主题。

## 待补验证

- [ ] 六源持续运行及完整分页的实服验收；2026-11-07 六源连通性通过仅证明当次轻量探测。
- [ ] 完整生产备份在独立主机的恢复、Redis 队列重建与采集连续性。
- [ ] 安装并启用 1Password 的实际浏览器复测；已验证按钮类型和站点行为，尚未直接验证扩展弹窗。
- [ ] 更大材料范围下的模型结果与人工评估；已有公开摘要 canary 不代表全文阅读或科学核验通过。

## 维护方式

完成事项移入 changelog，并更新对应功能或操作文档。涉及数据、权限、迁移或费用的事项，需要同时给出实现、验证证据和运行条件；不以测试条目数量代替实际覆盖。
