# 简单管理指南

Glean 将个人阅读、共享审核和来源证据分开保存。管理入口只面向管理员；没有审批链、任务分派或额外工作流。

## 1. 账号与独立记录

管理员进入「用户管理」，搜索用户或打开统一的新建/编辑表单：

- 新建时输入用户名、初始密码、昵称，选择普通用户或管理员，并设置是否启用。
- 编辑时修改昵称、类型和启用状态；用户名与密码不在编辑范围。既有角色授权与联系信息不会被这张简化表单清空。
- 当前账号不能禁用或降级自己；后端同样校验管理员权限，不仅隐藏按钮。
- 不提供自行注册、密码重置或用户删除按钮。初始管理员仍通过既有本地 setup/seed 流程建立，不新增公开管理员注册入口。

所有人共享论文与研究主题，但阅读状态、隐藏和保存的筛选偏好按用户隔离。个人隐藏对该用户的所有主题生效，可在已隐藏视图恢复，不改变别人看到的目录或科学结论。

## 2. 待审、标注与移出主题

在论文详情展开「论文管理」，按研究主题直接保存一次决定：

| 决定     | 结果                                       |
| -------- | ------------------------------------------ |
| 待审核   | 进入该主题待审集合                         |
| 纳入     | 进入该主题精选目录                         |
| 移出主题 | 进入该主题已移出集合，可再次改为纳入或待审 |

备注与手动标签随该主题审核一起保存，对其他用户可见。当前主题排在前面；一篇论文在不同主题可以有不同决定。历史记录首次人工处理须明确选择，不能把尚未处理的历史“待核”默认保存成待审。新发现的真实来源论文仍先待审；mock LLM 不构成人工纳入。队列统一叫「待审核」，可以同时包含管理员标记待审的历史论文和真实新发现；只有 `origin=live` 表示新增来源论文，人工待审不改变原始来源或 raw 分类。

移出主题**不删除论文或成员关系**，不影响其他主题、个人阅读/隐藏或原始证据。精选范围在尚无人工决定时沿用原历史规则；人工决定优先影响当前集合。全部记录仍保留各类记录。

## 3. 书目纠错与来源保留

「元数据纠错」仅支持原文标题、中文标题、作者、发表年份、期刊/会议和摘要。勾选需要纠正的字段，填写内容和纠错原因后保存。取消某项勾选再保存，就撤销该项覆盖、恢复来源值；不是把字段清空。

纠错属于同一论文的共享展示层，作用于所有主题；列表、详情及相应检索、年份/期刊筛选和排序使用有效值。原始 raw、来源观察与身份标识保留。DOI、arXiv 标识只读，日期与 URL 不支持在此编辑，不通过纠错进行论文合并。

「修改历史」展示该论文最近 **100** 次人工修改的操作者、时间和前后值。页面自动携带版本号防止覆盖别人的更新；发生冲突时重新读取再编辑即可，不需手工维护版本。

## 4. 新增、编辑与暂停研究主题

打开「研究主题」→「新增研究主题」，填写名称、说明、纳入规则与检索词组，选择是否参与后续扫描并保存。新主题会进入导航，可直接打开论文工作台；空主题显示真实空状态，不填充演示论文。

检索词组每行一组，组内用 `|` 分隔同义词：**同组 OR，不同组 AND**。启用新主题检索时必须提供词组。已有三个主题保留原规则与历史筛选；内置主题不设置覆盖词组时沿用原检索模板。主题标识创建后固定，修改显示名称不会重命名旧成员关系。

暂停只影响后续新扫描的主题配置，既有论文仍可查看。每次扫描冻结当次模板快照；编辑或暂停后，旧运行的恢复/重试继续用原快照，新的扫描窗口才读取新配置。旧版无快照运行仅在原静态模板版本匹配时恢复，不猜测当前配置。

**保存主题不会立即抓取，也不会开启全局调度。** 全局调度与运行账号仍由既有后端配置管理；同一已完成窗口的幂等行为不因主题编辑而改变。

## 升级与验证边界

管理表通过 `db/migrations/20261027163000_catalog_management.sql` 加入。已有数据库沿用[根目录的 Atlas 迁移流程](../../README.md#本地启动)，先迁移再启动新代码，不重新 seed 管理员、不清库。

接口与权限细节见 [API 契约](api-contract.md)。组件模拟测试、真实 PostgreSQL 事务测试与真实 API 浏览器验收是不同层级，应以对应提交的执行结果为准；测试清单或成功编译不代表端到端通过。现有 README 截图有独立提交来源，尚未覆盖管理界面。本模块不代表生产部署或真实 LLM 接入完成。
