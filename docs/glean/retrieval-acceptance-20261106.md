# 通用检索改造：实现与实际验收记录

日期：2026-11-06。对应《通用文献检索与 Glean 改造完整需求包》24 项需求、23 项验收定义。需求包 24 个原文件的长度和 SHA256 已核对；恢复 patch 与 bundle 在基线 `1060363` 上得到相同目标 tree `e3910fc8740d0bda59aecafe932ecddc15665f14`。

本轮接入既有检索改造，补齐协议映射、长期请求账本、导出、人工证据门槛和累计预算。没有发布、推送、合并或部署本分支；线上环境不因此改变。提交按功能拆分，Ent 生成文件随 schema 提交。具体使用方法见[主题检索计划](search-plans.md)。

## 实际执行结果

- PostgreSQL **17.11** 以正常客户端 TCP 连接运行在一次性本地测试环境；全部 9 份迁移实际应用。catalog/monitor 客户端业务、事务回滚、独立事务并发、跨进程恢复测试均已执行，没有以 skip 计通过。独立浏览器数据库导入 **39,495** 条历史主题成员关系，零隔离。
- `go test ./... -count=1` 使用真实测试 DSN。除 Windows 上既有 `TestDeploymentBaseTransfer` 的 POSIX 路径/符号链接用例外通过；该测试的 Linux 二进制随后在 WSL Ubuntu 实际执行，**14 个子用例全部通过**。因此不把 Windows 原命令写成全绿。
- `go generate ./internal/data` 无生成漂移；`go vet ./...` 与 `go build -o ./tmp/server.exe ./cmd/server` 通过。新导出修正后再次执行 catalog 测试。
- 前端 **238/238** 单元测试通过，typecheck、lint、生产构建通过。新增表单独立提交的隔离检出也通过 18 项相关测试。
- Chromium 真实 Go/PostgreSQL 浏览器流程：桌面历史目录、手机历史目录、用户/主题/审核/纠错管理、非生物医学协议导入/确认/保存/重载/无效编辑、改密及会话撤销均通过。协议用例首次因整页重载后没有重新登录失败，按内存凭据设计修正测试后重跑通过。不是声称第一次完整运行零失败。
- 真实 Europe PMC CLI 以 **1 页、page size=1** 上限获取并入库 **1 条**观察；模型和材料请求关闭。桌面/手机页面检查来源、发现路径、请求账本和 ZIP 下载通过。两个 ZIP 均通过 CRC、10 个文件 SHA256/字节数检查，**1 request / 1 occurrence / 1 canonical record** 对账一致，覆盖保持 partial。
- 已实际检查桌面目录、手机主题、协议预览和手机请求账本截图；未生成 HAR、trace 或持久登录状态文件。

### 模型实服检查

`TestLiveModelPipelineCanary` 取得真实 Europe PMC 公开摘要 `PPR:PPR1348014`，实际阅读范围 `abstract_only`，材料 SHA256 `6d1677560563b1279ca1c08fce8f4834bd821c5c687291e57fa9774d3beb8dc8`。

成功链路共 4 次模型调用：Jev 分类、gpt-6.1-terra 总结、gpt-6.1-terra 独立复审、Jev 证据检查。实际 Jev 返回版本 `jev-1.14.0`；供应商报告合计输入 8,653、输出 1,666 tokens。密钥仅注入测试进程，没有保存进仓库配置、日志或导出。

此前 Jev 实服尝试暴露独立两位小数舍入导致旧校验过严，已以有界舍入容差修正并添加回归；没有修改供应商分数。协议依据见 [Jev score 原语](https://docs.typesafe.ai/primitives/score) 与 [System One 快速开始](https://docs.typesafe.ai/introduction/quickstart)。

程序确定性证据检查仍返回 **1 项问题，supported=false**。这是保留模型与程序分歧的正确结果，不是全文或科学核验通过。该测试不启用生产队列。
