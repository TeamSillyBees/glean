# 产品目标与验收标准

Glean 的目标是成为可长期使用、界面友好、交互顺手、获取及时、信息丰富的文献平台，而不是只有测试通过的演示工程。

## 不可混淆的边界

- Jev 与生成式 LLM 使用显式配置的真实 HTTP adapter；缺少配置时等待，不用 mock 冒充处理完成。实服模型验收须另行提供配置与密钥。
- 文献来源、HTTP 请求、数据库、增量进度、去重、版本记录、调度、入库和前端查询均使用真实实现。
- 测试可以使用 fixture/fake 做可重复的单元测试，但应用运行路径不能悄悄退回模拟来源、虚假文献或仅内存状态。
- 真实论文、实际阅读材料与机器输出必须分开标识。取得摘要不代表全文阅读；任何模型输出不代表科学核验，更不能覆盖历史或人工核验结论。
- 不改仓库元数据；按功能或阶段提交 main，避免巨型单次提交和零碎文件级提交。

## 四个验收面

1. **好用的界面**：三个主题导航、清晰的筛选顺序、可恢复的阅读/隐藏状态、丰富但不堆砌术语的论文详情、移动端可用、加载/空/失败状态可理解。
2. **及时的真实获取**：按来源成功水位和固定窗口处理，每 72 小时增量；支持重叠补漏、延迟收录、新版本与正式发表事件；失败不伪装成零新增。
3. **信息与证据丰富**：保留原题名/摘要/作者、主题相关信息、出版载体、正式在线与卷期日期、来源链接、版本历史、首次发现和更新时间。未知值保持未知，不用零或补齐日期伪造完整性。
4. **可持续维护**：真实 PostgreSQL、幂等导入、可续跑任务、有界重试、限流、可观察覆盖缺口、历史结论保护、真实后端浏览器验收与持续代码审查。

## 真实链路验收

- 公共官方 API 有界采集真实记录，并保留端点、时间、响应状态和分页完整性证据。
- 来源记录通过实际数据库保存，再由真实查询 API 返回给前端。
- 完整 39,495 条历史主题成员关系可校验和幂等导入，不只展示少量示例。
- 浏览器验收调用实际 Go API 与 PostgreSQL；桌面与移动端截图用于检查布局，不能用路由伪造数据来冒充全链路。
- 真实 LLM 接入、外部生产部署与需要额外账户/密钥的服务单独标明，不能以这些未提供条件为由停止其他真实功能开发。
